# 2026-6303-1-conference-agent

ИИ-агент для автоматизации сбора, структурирования и поиска информации о научных конференциях.

## 📌 Что делает продукт

- Загрузка PDF или скана с положением конференции
- Автоматическое распознавание текста (OCR) и извлечение данных
- Ручная проверка и редактирование извлечённой информации
- Автоматический подбор хэштегов + возможность добавить свои
- Генерация поста через ИИ (OpenRouter) и публикация в Telegram-канал
- Добавление новых администраторов с сохранением в базу данных
---

### Сценарии работы
**Сценарий 1 — Пополнение базы данных:**
1. Администратор загружает PDF-файл с положением конференции
2. ИИ-агент извлекает текст (OCR) и структурирует данные
3. Администратор проверяет и при необходимости правит данные вручную
4. Данные сохраняются в БД
5. ИИ-агент генерирует пост для Telegram-канала по выбранному шаблону

**Сценарий 2 — Администратор недоволен постом:**
1. Администратор оставляет комментарий к сгенерированному посту
2. ИИ-агент перегенерирует пост с учётом замечаний

## 🚀 Как запустить
### 1. Клонирование репозитория
```bash
git clone https://github.com/algorithm-ssau/2026-6303-1-conference-agent
cd 2026-6303-1-conference-agent
```

### 2. Установка зависимостей
```bash
pip install -r requirements.txt
```

**Основные библиотеки:**
- `aiogram` — фреймворк для Telegram Bot API
- `pymupdf` + `easyocr` — извлечение текста из PDF
- `pydantic` — модели данных и валидация
- `pandas` — экспорт данных в Excel
- `requests` — HTTP-запросы к API LLM-провайдеров
- `pytest` — модульное тестирование

### 3. Настройка конфигурации
**Telegram-бот** (`src/conference-bot/bot/config.py`):
```python
TOKEN = "ваш_токен_бота"              # или os.getenv("BOT_TOKEN")
ADMIN_IDS = [ваш_telegram_id]          # список ID администраторов
PROXY_URL = "https://api.telegram.org" # или свой прокси-сервер
OPENROUTER_API_KEY = "ваш_ключ"        # для генерации постов и парсинга
```
> 🔒 **Важно:** Не коммитьте реальные токены в репозиторий. Используйте переменные окружения или `.env`-файл.

### 4. Инициализация базы данных
Модуль БД находится в папке `database/`. Для создания таблиц:
```python
from database.schema import init_db
init_db()  # создаст файл conferences.db в корне проекта
```

### 5. Запуск бота
```bash
cd src/conference-bot
python main.py
```
Бот запустится с обработкой сетевых ошибок и автоматическим переподключением при сбоях соединения (реализована обработка `TelegramNetworkError` и `TelegramRetryAfter`).

### Схема базы данных (SQLite)

**Таблица `conferences`:**
Содержит расширенные атрибуты для всей информации, полученной от парсера, включая хэштеги и векторные представления.

**Основные функции (в `database/db_manager.py`):**

*   `add_conference()` — добавление с проверкой на дубликаты
*   `search_conferences()` — поиск с фильтрацией по активным и дедлайнам
*   `get_active_conferences()` — все активные с будущим дедлайном
*   `archive_past_conferences()` — автоматическая архивация прошедших

**Таблица `conferences` (ключевые поля):**

| Поле                 | Тип       | Назначение                                  |
|----------------------|-----------|---------------------------------------------|
| `name`               | TEXT      | Название конференции                        |
| `event_type`         | TEXT      | Тип (конференция, школа, конкурс)           |
| `dates`              | TEXT      | Даты проведения                             |
| `location`           | TEXT      | Место проведения                            |
| `submission_deadline`| TEXT      | Крайний срок подачи заявки                  |
| `topics`             | TEXT      | Хэштеги и тематики                          |
| `is_archived`        | INTEGER   | Статус активности (0/1)                     |
| `vector`             | BLOB      | Векторное представление для поиска          |

### Цепочка обработки данных

```text
PDF-файл 
  ↓
PyMuPDF / EasyOCR (OCR) — извлечение текста
  ↓
LLM-парсер (OpenRouter/Groq) — структурирование в EventData
  ↓
Проверка администратором → ручные правки при необходимости
  ↓
Сохранение в SQLite (conferences.db) с хэштегами и векторами
  ↓
OpenRouter API → генерация поста по выбранному шаблону
  ↓
Публикация в Telegram-канал
```

### Принцип работы с ИИ

Проект использует LLM (в основном OpenRouter, с fallback на Groq) для:

1. Извлечения структурированных данных из текста положений конференций.
2. Подбора и генерации хэштегов на основе тематики конференции.
3. Генерации постов для Telegram-канала по 5 шаблонам (`social`, `blog`, `news`, `teaser`, `default`).

Благодаря fallback-стратегии, если одна модель недоступна, система автоматически переключается на следующую.

## 🛡️ Примечания

*   Токены и API-ключи хранятся в `config.py` и не должны коммититься.
*   Файл базы данных `conferences.db` добавлен в `.gitignore`.
*   Для стабильности соединения используется прокси (Cloudflare).
*   Реализована автоматическая обработка сетевых ошибок (`TelegramNetworkError`, `TelegramRetryAfter`).
*   Длительные операции (OCR) выполняются асинхронно для избежания блокировок.
*   Даты в БД хранятся в формате `YYYY-MM-DD`.
